# TL-001A synthetic paper intent and ambiguous submission recovery

Status: bounded [issue #2](https://github.com/Loothore907/tidelab/issues/2) engine evaluation, 2026-09-23 Alaska time. No engine is adopted. All orders, IDs, account values and reports are TideLab-authored synthetic doubles; no account, credential, real market data or live order was used.

## Probe

The [paper submission barrier](TL-001A-LEAN-PAPER-SUBMISSION-BARRIER.md) serialized correction intake and mock submission but lost its unknown-submission hold on process exit. This probe adds a test-only durable intent with a stable client ID and exact snapshot revision, quantity and price. A replaceable local paper-order authority persists a broker ID and pending order report under that client ID. The coordinator validates the source's account/execution snapshot before a conditional submission. Its file writes flush a candidate and rename it on the same filesystem; this is local crash-window evidence, not a cross-host durability claim.

Two isolated scenarios force process exit. First, the intent is flushed before any broker call. A new process finds authoritative **absence** in the single-writer local paper source, submits that same ID once, and marks the intent accepted. Second, the broker report is written but acknowledgement is lost. A new process finds the exact order, marks the pending intent accepted and sends no new submission. Repeating recovery sends none. Separate report fixtures return unknown or conflicting order details; both hold with the intent pending and zero submissions. The report comparison includes client/broker IDs, snapshot revision, quantity, limit price, account cash/holding and pending status.

`TL001A_INTENT_ONLY=1 bash scripts/lean_fallback/run_forward_recovery_probe.sh <pinned-LEAN-checkout> <dotnet-10-binary>` and the full recovery runner passed locally at pinned LEAN source `88bce0fc6fe282378ee73c54cef1090d0d7a73ee`. The build had zero errors and existing upstream package-audit warnings. The focused runner printed `RECOVERED_ABSENT new_submissions=1`, `RECOVERED_EXISTING new_submissions=0` on repeated recovery, `BLOCK_UNKNOWN_REPORT new_submissions=0`, and `BLOCK_CONFLICTING_REPORT new_submissions=0`. Repository CI does not compile the C# probe.

## Decision effect and limits

This is a plausible replaceable forward-paper intent/authority protocol with a single writer and definitive local lookup. It does not prove a broker's absence report is final, that LEAN's own order state is reconciled, or that the account and execution-ID delivery paths stay in sync after a new order. It does not test a failure during the atomic rename, concurrent process writers, or real filesystem power-loss durability. The source must also enforce one submission route; direct calls around it would bypass the gate. An external broker would need native client-ID/idempotency and authoritative query guarantees, plus separate authorization.

LEAN remains the stronger candidate for continued evaluation because the synthetic historical/forward decision path and public startup seam are demonstrated, but the host still owns this intent protocol and the join to LEAN order/account recovery. NautilusTrader `2.0.0rc5` still has the external Python data-client/backing incompatibility. Neither engine is adopted. Next test a single joined paper restart path that reconciles this intent, the broker order/execution report, and LEAN's restored order/account state before allowing another order. Realistic cost/fill behavior, experiment identity and distribution obligations remain open. Keep [TL-001B issue #3](https://github.com/Loothore907/tidelab/issues/3) separate.
