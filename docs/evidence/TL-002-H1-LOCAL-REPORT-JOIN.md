# TL-002: synthetic H1 proposal and local report join

Date: 2026-09-24/25. Owner: [issue #48](https://github.com/Loothore907/tidelab/issues/48). This checkpoint uses invented reports and accounts only.

The earlier H1 bridge persisted the frozen C# policy proposal as an SQLite intent with a stable variable client ID, quantity, source revision, and product-rule identity. `H1LocalReportJoin` now accepts a complete, revisioned **test-owned** report for that same proposal. It binds client, instrument, side/quantity/limit, source revision, LEAN order ID, and broker ID; records each execution ID once; and checks reconstructed cash and inventory against the report before committing. Repeated identical reports are idempotent. A changed report at the same revision, missing or corrected execution, skipped revision, invalid account, or unknown order identity holds. **Even a filled or canceled report leaves the paper-intent barrier unresolved** until a later slice joins the final account to the next opening account and establishes safe report finality. No subsequent proposal is admitted by this checkpoint.

Targeted synthetic checks cover restart after a partial buy, cancellation and next-intent hold, two partial executions completing one buy, a full-inventory sell, changed fill, duplicate ID, stale revision, and wrong cash or client identity. The report is a controlled local fixture in Python, **not yet emitted by the pinned LEAN brokerage path**. The current code does not deliver or correct LEAN order events, prove a broker's report finality, bind the next opening account to the previous final account, or handle an external account. A late correction requires a reversal protocol; do not treat this fixture as unattended paper safety.
