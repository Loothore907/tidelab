# H1 v1 synthetic paper proposal and durable intent

Issue: [TL-002 #48](https://github.com/Loothore907/tidelab/issues/48). This is an invented-data integration check, not a forward trading result or order authority.

The same `TideLabH1V1Policy` used in the historical and forward decision probes produced a warmed entry decision. `TideLabH1V1PaperBoundary` converted that decision and an invented opening account snapshot into a stable client ID and 25% sized buy proposal. It also converted the next exit decision into a sell proposal for the full supplied inventory. Both require the opening observation at the closed hour's boundary. The JSON carries the policy decision, source revision, account amounts, quantity, and price; no LEAN order method is called.

`H1SyntheticPaperBridge` checked the proposal's stable identity, time, source revision, sizing, policy/risk fields, and versioned invented product rules, then persisted it through the existing SQLite `PaperIntentStore`. The bridge retains a hash of the entire proposal, opening time, revision, and rules identity. The durable claim is written as `submission_unknown` before a synthetic local order source may write. A restarted bridge could not claim the same ID again. An unresolved first intent blocked a later new ID; a conflicting source order held rather than changing the intent. The local source wrote exactly one invented order. Missing, late, changed, or unsupported terms held before new submission.

Observed checks: 49 Python tests passed (one optional Nautilus test skipped because the package was absent); the standalone .NET H1 policy, accounting, and proposal check passed; its emitted JSON was consumed by `scripts/verify_h1_paper_proposal.py`, which reported `restart_claim=blocked local_order=one unresolved=hold`. The generated JSON was kept in ignored local `data/`, outside Git. `git diff --check` found no whitespace errors. These are local checks; the PR's exact-head CI is separate.

The opening account snapshot and invented local order source are test-owned. No authoritative execution report, fee, cash/inventory correction, partial fill, or LEAN brokerage submission is joined to this H1 proposal yet. A real broker cannot use this local source's absence result to justify a retry. The next #48 slice must join proposal identity and quantity to the existing LEAN report/journal, including partial/canceled/corrected outcomes, and keep a new proposal blocked until the previous order and account are reconciled. The on-time data source remains independent under [issue #3](https://github.com/Loothore907/tidelab/issues/3).
