# TL-002 synthetic local order reconciliation

Status: bounded [issue #48](https://github.com/Loothore907/tidelab/issues/48) runtime-control slice, 2026-09-24. This adds no LEAN brokerage adapter, external broker, account access, market data or live order.

`SyntheticLocalPaperSource` writes a test-only submitted order beside TideLab's durable intent in one SQLite authority. The source copies the exact client ID, instrument, side, decimal quantity, limit price and source revision from the claimed intent, and derives a stable synthetic broker ID. SQLite serializes the write and the subsequent report lookup across processes. A repeated call with the same ID cannot create a second order; conflicting report terms hold rather than changing the intent.

Two spawned processes deliberately exit after the durable claim. In the first window, no local source row was written. A fresh process observes definitive **local** absence, rearms that same client ID, and records one order. In the second window, the row was written before acknowledgment was lost. Recovery sees the exact order twice, holds the intent unknown, and creates no second row. A corrupted quantity in the local report blocks recovery; the intent remains unknown. These tests validate only the same-database synthetic source. Its absence is authoritative because this test double is the only writer of synthetic orders; it cannot be used to infer absence from LEAN, an external process, or an exchange.

The present record is an order-identity boundary, not an accounting ledger: there are no executions, fees, cash, holdings, corrections, cancels, rejects, or forward sells. A later order is still blocked. Next join the selected pinned LEAN public brokerage path to a replaceable local paper report and reconcile the engine's order/account state with an execution journal before lifting that hold. No unattended paper safety or profitability result follows from this slice. TL-001B data rights remain independent.
