# H1 v1 local trial-attempt record

Issue: [TL-002 #48](https://github.com/Loothore907/tidelab/issues/48). The [H1 v1 preregistration](../experiments/H1-V1-PREREGISTRATION.md) requires exact code, configuration, cost and data identities plus every failed or aborted attempt before opening validation or untouched results. This slice records those facts without storing market data or performance output in Git.

`TrialRegistry` validates the existing portable experiment identity and writes a local SQLite attempt row **before** a command runs. Completion, failure or abort is a separate immutable row with a reason code and optional log hash. A crash leaves an open attempt; another attempt for that strategy version is held until its status is resolved. Development reruns can be recorded after closure. A validation identity can open once; the untouched partition can open once for a strategy version, including a failed or aborted opening. A correction needs a new trial identity or strategy version as the preregistration requires. SQLite uniqueness constraints and update/delete triggers guard accidental rewriting, while this local database is not tamper-proof evidence.

The standalone .NET H1 check now loads its invented input from a versioned JSON fixture. The local identity export hashes those exact fixture bytes, the frozen H1 specification, the cost replay source and the committed TideLab revision, along with pinned LEAN's source revision. `record_local_trial.py` accepts an identity manifest and runs a command while retaining the log and registry under ignored `data/`. A command error is recorded as a failed attempt; process interruption is recorded as aborted when the wrapper can handle it. A power failure leaves an open attempt. Each new launch needs a unique attempt ID and log path.

Local checks before integration: 52 Python tests passed, with one optional Nautilus test skipped because its package was absent. The standalone .NET decision, accounting and paper-proposal checks passed using the external invented-input fixture. No real market data or strategy performance was read. The identity export and recorded command will be exercised after merge so their code revision identifies the integrated commit. Exact-head PR and merged-main CI remain separate checks.

This is the trial-record foundation, not a complete historical evaluation runner. The H1 proposal still needs LEAN execution/account reconciliation, and the historical run requires a current rights and input-provenance check. Issue #3 separately gates on-time forward data.
