# TL-002: pinned LEAN synthetic H1 report and account handoff

Date: 2026-09-25. Owner: [issue #48](https://github.com/Loothore907/tidelab/issues/48). All prices, accounts, reports, and product rules in this check are invented.

The frozen C# H1 policy emitted a 25-unit entry proposal at a synthetic opening. A separate process prepared that proposal in SQLite. The pinned LEAN checkout at `88bce0fc6fe282378ee73c54cef1090d0d7a73ee` routed one `QCAlgorithm.LimitOrder` through a mock brokerage. Its callback claimed the SQLite intent as `submission_unknown` before writing a versioned local report with the LEAN order ID, stable broker ID, variable client ID, quantity, limit, cash, and holding. Subsequent processes advanced the controlled report to a 10-unit partial fill (99 price, 0.1 fee), then cancellation of the remainder. `H1LocalReportJoin` checked every revision and execution against the original proposal and reconstructed account before LEAN setup. Fresh setup restored 10 units and 9009.9 cash twice without a new submission.

Cancellation alone kept the first intent unresolved. A separate handoff took the exact terminal report hash as the next account revision, verified the next hour, instrument, experiment, cash, inventory, and marked equity, then committed the first resolution and next proposal together in one SQLite transaction. The same frozen C# H1 policy produced a 10-unit exit proposal from the reconciled holding. LEAN routed its signed sell order once; a fresh setup adopted its submitted report with zero additional submissions. Repeating the handoff was idempotent. In an independent database, a changed price for an already recorded execution was rejected by the SQLite journal, and the attempted LEAN restore stopped before setup; the first intent remained unknown.

Run the focused probe with `TL_H1_REPORT_ONLY=1 bash scripts/lean_fallback/run_forward_recovery_probe.sh <separate-pinned-LEAN-checkout> <dotnet-10-binary>`. The 2026-09-25 run built the pinned test runner with 0 errors and 136 existing dependency/toolchain warnings, then passed the submitted, partial, cancel, restore, next exit, and correction-hold paths. The Python H1 bridge/report tests passed (13 tests). The LEAN checkout was a separate detached worktree; the older checkout's generated files were left untouched.

This establishes one controlled single-writer synthetic report protocol. LEAN produced the initial order and ID, while the test fixture produced later broker statuses, executions, and balances. It does not prove an external broker's finality, atomic report/account snapshot, late-correction protocol, realistic fill, or unattended forward operation. The next #48 gate is to connect the same H1 policy/account flow to conservative execution and the registered historical trial without weakening correction or unknown-order holds. Issue #3 independently owns timely forward data. No real market data or public real-data artifact was used here.
